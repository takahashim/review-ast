# Re:VEIWでの版面設計: 設定項目と各エンジン(LaTeX, Vivliostyle, Typst)での対応について

## 0. 背景

- 現在、Re:VIEW AST版(review-ast)ではASTによる文書構造モデルの整備と並行して、PDF組版エンジンとしてLaTeXの他にVivliostyleとTypstのサポートを試みている
- これまでの版面設計はLaTeXにおけるreview-jsbookとreview-jlreqのクラスファイル群として既定されており、他のエンジンとの共有は考慮されていなかった

## 1. 目的と想定読者

- 本文書の想定読者は、書籍の版面を設計・調整する人とする
- 本文書だけで、一つの版面設計を LaTeX(review-jsbook/jlreq)・CSS 組版(Vivliostyle)・Typst(review-book)のいずれにも転用できることを目指す

## 2. 版面のモデル

### 2.1 判型と仕上がり

- 設計値: 仕上がり寸法(判型)、綴じ方向、片面か見開きか
- 判型は名前(`jis-b5` など)で指定する。名前と実寸の対応表はライブラリが持つ
- 名前を持つのは A/B 系の定型だけである。四六判のような伝統判型や変型判は、どのエンジンでも実寸で指定する(review-jlreq は `paper={127mm,188mm}`、CSS は `--papersize-width/height`、Typst は `crop.trim`)
- 仕上がり(トリム後の寸法)と用紙(印刷する紙の寸法)は別概念である。用紙は 2.10 で扱う
- 日本の B5 は JIS B5(182×257mm)であり、ISO B5(176×250mm)ではない。判型名で指定するのはこの取り違えを防ぐためでもある

### 2.2 基本版面の導出

- 版面(本文が組まれる矩形)は寸法で直接指定しない。「字詰め × 級数」が幅、「行数 × 行送り」が高さとして導出する
  - JIS X 4051 / JLReq の基本版面の考え方に従う
- 直接指定しない理由:版面の意味は「1行何字・1ページ何行」にあり、寸法はその結果にすぎない。寸法で持つと、級数を変えたときに字詰めが半端になる
- 既定値:字詰め40字、級数13Q、行数35行、行送り21.65Q(jsbook の 10pt/15.4pt 相当)
  - この一組は判型 jis-b5 を前提にした値である(以降の章の既定値も同様)。適切な組みは判型ごとに異なるため、判型を変えるときは字詰め・行数を選び直す。余白も同様(2.3)
- 行送りを設計として選び直すなら 22Q のような丸い値にする

### 2.3 余白の規約

- 余白は各軸に二つある(天/地、ノド/小口)。4つとも指定できるが、基本形は天とノドの指定である
- 無指定の軸は中央寄せになる。天と地はどちらも与えなければ同じ値(天地中央)、ノドと小口も同じ値(左右中央)になる
  - これは review-jsbook / review-jlreq の既定と同じ意味論であり、他のエンジンでも追従する
- 一方だけ指定すればそちらが確定し、他方は判型と版面の大きさから導出される。地から積む設計・小口基準の設計のために、地・小口の側を陽に指定してもよい
- 一方だけの指定なら、ノドを広げれば小口が同じだけ狭くなり、版面そのものは動かない
- 同じ軸の両方を指定する形は、組み(2.2)の字詰め・行数と両立しない「余白から版面を設計する」別方式になる。review-jlreq(jlreq)はこの方式も持つが、この語彙の基本は組みから設計であり、余白からの設計は持ち込まない
- 既定値(jis-b5 のとき):天30mm、ノド26mm。ノド26mm はこの判型・この組みでは左右中央と一致する値であり、左右を取り違えて入稿しても紙面が破綻しない。綴じ代が要るときだけ広げる。天30mm は天地中央(約33.8mm)よりわずかに上寄せの明示指定である
- この規約が契約するのは入力と導出関係の意味論(どの余白を受け付け、無指定が何を意味するか)だけである。解決をどこで実装するか(クラス、実装 CSS、テーマ関数)はエンジンごとに異なってよく、エンジンが入力の一部(地・小口の陽指定)を未対応のまま出発することも許す。対応状況は3章の表に、追いつかせる作業は9章に記す

### 2.4 単位

- 級数と歯送りは Q・歯(H)で書く。1Q = 1H = 0.25mm。寸法は mm で書く
- pt は使わない。
  - TeX の pt(1/72.27インチ)と CSS/Typst の pt(1/72インチ)は 0.37% 違い、取り違えると紙面がずれる
  - LaTeX 版の pt 指定を他エンジンに持ち込むときは Q か mm に直す
  - 例外は罫線の太さ(柱の罫 0.4pt、トンボ 0.3pt)。慣用の pt 値をそのまま使う。0.37% の差は罫の太さでは意味を持たないため
- 各エンジンでの Q の書き方:CSS はそのまま書ける(`13Q`)。Typst には Q がないので `Q(13)` 関数で mm に直す。jlreq/review-jsbook は `13Q`・`22H` が書ける

### 2.5 行送りの決定性

- 行送りは設計値であり、フォントのメトリクスに依存させない。baseline 間 = 行送り、が常に成り立つことを想定する
  - これが崩れると「21.65Q」という設計値が意味を失い、書体を差し替えただけで行数が変わる
- 各エンジンで決定性を得る方法は実装章(4〜6章)に置く。既定のままでは決定的にならないエンジン(Typst)がある

### 2.6 級数表

- 本文以外の級数は、絶対値ではなく本文級数の倍率で持つ。本文を変えれば全体が追随する
- 既定の表(右は本文13Qのときの実寸と LaTeX の対応):

| 名前 | 倍率 (LaTeX) | 実寸 | LaTeX | 用途 |
|---|---|---|---|---|
| xxlarge | 2.5 (2.488) | 32.5Q | `\Huge` | 章見出し・大扉 |
| xlarge | 2.0 (2.074) | 26Q | `\huge` | 章番号・部番号 |
| large | 1.4 (1.44) | 18.2Q | `\Large` | 節見出し |
| medium | 1.2 (1.2) | 15.6Q | `\large` | 小見出し・コラム |
| normal | 1.0 (1.0) | 13Q | `\normalsize` | 本文 |
| small | 0.9 (0.9) | 11.7Q | `\small` | キャプション・表 |
| xsmall | 0.8 (0.8) | 10.4Q | `\footnotesize` | コード・脚注 |

- 柱とノンブルの級数の既定は本文と同寸(本文級数に追随)。LaTeX 版の柱・ノンブル(fancyhdr)にサイズ指定がなく本文級数のまま組まれるのに合わせた。小さくしたいときは実寸(Q)で上書きする
- 倍率の由来は LaTeX クラスの標準サイズ命令の系列(1.2 の冪:1.2、1.44、1.728、2.074、2.488)である。0.8・0.9・1.2 は一致し、1.4・2.0・2.5 は 1.44・2.074・2.488 を設計値として丸めた値である
- 系列のうち 1.728(`\LARGE`)には対応する段を設けていない。jsbook での用途は標準 `\maketitle` の書名だけで、Re:VIEW は大扉を自前で組む(`\Huge`・`\Large`・`\huge`)ため、紙面に現れないからである
- したがって表の LaTeX 列は「同じ用途の命令」の対応であり、実寸は完全には一致しない。LaTeX はクラス定義の寸法、CSS・Typst は丸めた倍率で組まれる(7.2)

### 2.7 書体

- 本文(明朝系)・見出し(ゴシック系)・コード(等幅)の3系統を持つ
- 和欧混植のフォールバック列は「欧文, 和文」の順に連結する
- 総称ファミリ(serif / sans-serif / monospace)は連結後の末尾に置く。
  - 総称は必ず何かのフォントに解決されるため、途中に置くと、どの和文書体を使うかを明示リストではなく OS の総称マッピングが決めてしまい、環境によって組版結果が変わる
  - この規則は CSS のみに関わる。Typst のフォールバック列に総称ファミリの概念はなく、列が尽きるとエンジンの既定書体にフォールバックする
- 見出しはゴシック・サンセリフ・ボールドの組(LaTeX 版が `\headfont` を gt+sf+bf に再定義しているのと同じ)

### 2.8 和欧の大きさ

- 和欧は同寸で組むことを基本とする(決定)。和文と欧文を同じ級数で組み、倍率補正をしない
- jsbook 流(欧文を和文の約1.081倍で組む)を他のエンジンで使用することは棄却した。理由は次の3つ
  - jlreq の既定が同寸であり、LaTeX 側の今後の標準になる。jsbook の倍率の動機の一つは「10pt クラスの制約下で和文を 13Q 相当にする」という歴史的な換算であり、jlreq では `jafontsize=13Q` と直接書けるためこの動機は消滅している
  - Typst にフォールバック単位の大きさ補正の機構がなく、同寸だけが3系統に無損失に写せる。倍率を語彙に残すと、その値を使った時点で紙面一致が壊れる
  - CSS での再現(`@font-face` の `size-adjust` による合成フォント)は `var()` が使えず迂遠で、設計値ファイルの中で最も説明を要する箇所になっていた
- 同寸で欧文が小さく見える問題は、倍率ではなく書体選択で解く。見劣りの主因は x-height なので、x-height の大きい欧文を和文と組む。これはどのエンジンでも同じに写せ、契約を壊さない
- 欧文本文の既定フォールバック列は「x-height が大きく本文向き → 可用性」の順に並べる:XCharter(TeX 同梱)→ Charter(macOS 標準)→ Georgia(macOS/Windows 標準)→ Noto Serif(Linux/CI・オープン)→ Latin Modern / CMU Serif / Times New Roman(TeX・最終手段)。同寸で見劣りしていた Latin Modern(x-height が小さい)を筆頭から外し、環境をまたいで x-height の大きい欧文が当たるようにした。design.css(`--font-latin-serif`)と theme.typ(`fonts.body`)で同じ列を持つ。LaTeX の欧文書体は review-jsbook/jlreq(gem)の既定で、review-ast の設計値ファイルの外にあるため、揃えるにはプリアンブル/sty で書体を設定する(書籍または gem 側の作業)

### 2.9 版面の外

- 柱とノンブルは版面の外に置き、版面からのアキで位置を決める
- 設計値:柱の高さ、柱と版面のアキ(headsep、既定10mm)、版面とノンブルのアキ(footskip、既定10mm)
- 柱は章名を左、節名を右。ノンブルは版面下の中央(通常のノンブル。小口側・ノド中央に置くのは隠しノンブルで、別物=5.5)。描き方(罫の有無など)は体裁の領分で、この文書は位置だけを持つ

### 2.10 印刷用紙

- トンボと裁ち落とし(bleed、既定3mm)、仕上がりを載せる用紙(sheet)
- sheet は2通り:仕上がり+塗り足し+トンボ長が載るだけの用紙(auto)、または判型名で標準用紙を指定してその中央に仕上がりを置く
- 日本の印刷所は後者(A5 仕上がりを B5 用紙の中央に、のような形)を求めることが多い。review-jsbook の `media=print` と同じ考え方である
- CSS(Vivliostyle)は前者(auto)と、`--crop-offset` で一律ぶん大きい用紙の中央に置く形までを表せる。後者の判型名指定(軸ごとに余りが違う中央化)は crop-offset が全辺一律のため表せない(5.5、9.2)。Typst・LaTeX は判型名の後者に対応する
- トンボの既定色はレジストレーションブラック(CMYK)

## 3. 設計値の一覧

## 4. LaTeX(review-jsbook / review-jlreq)での指定

### 4.1 対応表

- LaTeX 経路のテンプレートは2つある。review-jsbook(jsbook.cls ベース)とreview-jlreq(jlreq ベース)。review-ast はどちらも同様にサポートし、どちらを使うかは書籍の事情で選べばよい。両者の指定の違い(判型名、級数の丸め、和欧の大きさ)はこの章に事実として記す
- CSS・Typst の版面の意味論(余白の中央寄せ既定、和欧同寸)は jlreq ベースに揃えてある。これは語彙の設計の話であり、LaTeX でのテンプレート選択を制約しない
- どちらも `config.yml` の `texdocumentclass` にクラスオプションとして書き、オプション名は共通である(区切りはアンダースコア)
- 同寸の決定(2.8)に整合するのは review-jlreq である。review-jsbook は jsbook の和文縮小(欧文比約1.081倍)を継承する

| 語彙 | クラスオプション |
|---|---|
| paper | `paper=b5`(review-jsbook では JIS B5)/ `paper=b5j`(review-jlreq。`b5` は ISO になる) |
| fontsize | `fontsize=13Q` |
| baselineskip | `baselineskip=21.65H` |
| line-length | `line_length=40zw` |
| number-of-lines | `number_of_lines=35` |
| head-space | `head_space=30mm`(無指定は天地中央) |
| foot-space | `foot_space=…`(review-jlreq のみ。無指定は天地中央) |
| gutter | `gutter=26mm`(無指定は左右中央) |
| fore-edge | `fore_edge=…`(review-jlreq のみ。無指定は左右中央) |
| headsep / footskip / headheight | `headsep=10mm` / `footskip=10mm` / `headheight=5mm` |
| 級数表 | `\Huge`〜`\footnotesize`(2.6の表の対応) |
| 和欧の大きさ | review-jlreq:既定(同寸)のまま何も指定しない。review-jsbook:jsbook の縮小が残る(上記) |
| crop.sheet / crop.bleed | `tombopaper=…`(既定は自動判定)/ `bleed_margin=…`(既定 3mm) |

### 4.2 導出の担い手

- 版面計算はクラス(cls)の側にある。字詰め・行数・級数を渡せば版面と余白の残りはクラスが導出し、無指定の余白は中央寄せになる。2.3 の余白の規約はこの意味論をそのまま採ったものである
- 字詰め・行数まで無指定にした場合、クラスは紙サイズから自動決定する(jsbook の挙動、jlreq は紙サイズの 0.75 倍)。この語彙の既定(jis-b5 の一組。2.2)とは別の値になりうるので、設計値を持つ書籍では組みを明示する
- review-jlreq は「余白から版面を設計する」方式(`head_space`+`foot_space`+`gutter`+`fore_edge` を全部与え、字詰め・行数を与えない)も持つ。この語彙では使わない(2.3)
- 指定しすぎた場合はエラーにならず黙って辻褄合わせされることがあるため、意図した行数・字詰めが出ているかを組み上がりで確認する

### 4.3 単位と丸めの注意

- `zw`(全角幅)は級数に連動する単位で、`line_length=40zw` は「40字」の意味になる
- Q・H はそのまま書ける。pt を書くときは TeX pt であることに注意(2.4)
- review-jsbook は fontsize を jsbook の飛び飛びのサイズ(8pt, 9pt, 10pt, …)に丸める。`13Q` は正確には出ない。他のエンジンとの設計値どおりの級数が要るときは review-jlreq を使う

### 4.4 トンボと入稿

- `media=print`(既定)でトンボとデジタルトンボが入り、`media=ebook` でトンボなし・表紙ありになる。用途の明示的な意思表示として与える
- トンボを載せる用紙は `tombopaper`(既定は自動判定)。2.10 の crop.sheet に対応する
- 隠しノンブルは `hiddenfolio=<プリセット>`(印刷所別のプリセットを持つ)。通しノンブルは `serial_pagination`、開始ページは `startpage`。これらはノンブルの入稿実務であり、版面設計の語彙には含めないが、Typst 側の対応状況は9章に挙げる

## 5. CSS(Vivliostyle)での指定

### 5.1 対応表

- 設計値は `style-vivliostyle-design.css` の `:root` に CSS 変数として置く。変数名は語彙と同名(`--head-space` など)
- 判型だけは名前でなく実寸(`--papersize-width/height`)で持つ。CSS の `size` に渡すため

| 語彙 | CSS |
|---|---|
| paper | `@page { size: var(--papersize-width) var(--papersize-height) }` |
| fontsize / baselineskip | `--fontsize: 13Q` / `--baselineskip: 21.65Q` |
| line-length / number-of-lines | `--line-length: 40` / `--number-of-lines: 35`(単位なしの数) |
| head-space / gutter | `--head-space` / `--gutter` |
| headsep / footskip / headheight | 同名の変数 |
| 級数表 | `--size-xxlarge` 〜 `--size-xsmall`(`calc(var(--fontsize) * 倍率)`) |
| 書体 | `--font-mincho/gothic/latin-*` を連結して `--font-body/heading/mono` |
| 和欧の大きさ | 同寸。何も指定しない(補正機構は持たない) |

### 5.2 導出の担い手

- CSS には版面導出の機構がないため、書き手が `calc()` で計算する。版面幅 = `calc(var(--line-length) * var(--fontsize))` のように、導出式は `style-vivliostyle.css`(実装側)に置き、設計値ファイルには値だけを置く
- 余白の優先順位(指定があれば使う、なければ導出)は、CSS に条件分岐はないが `var()` のフォールバックの入れ子で書ける。「天、なければ地から導出、どちらもなければ中央」を実装側の式に固定し、設計値ファイルは指定したい変数だけを定義する
- 左右ページの余白の振り分けは `@page :left` / `@page :right` で行う

### 5.3 行送りの決定性

- `line-height` に行送りの実寸を与えると行箱の高さは決定的になる(CSS のハーフレディングは半端を上下に等分するだけで、高さ自体はフォント非依存)
- 崩れるのは行内に大きい要素(級数の違うインライン、画像、上付き)が入ったとき。行箱が伸びて行送りが割れる
- 対策は実装側の領分(`line-height` の継承設計と `vertical-align` の管理)だが、「本文の行送りは設計値どおり、割れるのは例外要素の行だけ」という保証線をここで引く

### 5.4 版面の外

- 柱とノンブルはページマージンボックス(柱は `@top-left`/`@top-right`、ノンブルは `@bottom-center`)に置く
- 章名・節名は running element(`string-set` で拾い `content: string(...)` で流し込む)で柱に届ける
- headsep / footskip は、マージンボックスの寸法とパディングに換算して実現する(直接の対応物はない)

### 5.5 トンボと入稿

- トンボと裁ち落としは入稿用の上書き `style-vivliostyle-print.css` が `@page { marks: crop cross; bleed: var(--bleed) }` で有効にする。既定の `style-vivliostyle.css`(media=ebook 相当)は出さない。入稿版の設定ファイル(config-vivliostyle-print.yml)で design → 実装 → 入稿上書きの順に読み込む
- CSS の @page marks はトンボの長さ・太さ・色を制御できない(Vivliostyle の既定で描かれる)。CSS 側で持てる crop の設計値は裁ち落とし量(`--bleed`)だけで、長さ・太さ・色は Typst テーマの領分である(3章の表で crop.mark-length ほかが T のみなのはこのため)
- 仕上がりを大きい用紙の中央に置くには `--crop-offset`(既定 auto)に距離を与える。Vivliostyle の `crop-offset`(文法は `auto | LENGTH`)が仕上がりを一律その距離ぶん大きい用紙の中央に置く。ただし判型名の標準用紙(2.10 の後者。A5→B5 のように横17mm・縦23.5mm と軸で余りが違う中央化)は全辺一律の crop-offset では表せない。正確に判型名の用紙へ載せたいときは、auto の入稿 PDF を後段の面付け(Ghostscript / pdfjam など)で当該用紙に配置する。Typst・LaTeX(review-jsbook の media=print)は判型名指定に対応する
- 隠しノンブルは入稿用の上書きが `@page :right { @left-middle }` / `@page :left { @right-middle }`(横組み左綴じなので綴じ側は recto=左・verso=右)にノド天地中央のページ番号を出す。回転は `transform: rotate(-90deg)`(`text-orientation: sideways` は Vivliostyle が尊重せず正立のままになる。実測)。級数は `--hidden-folio-size`(既定 2.5mm、LaTeX の \scriptsize 相当)。柱・ノンブルを落とす面のルールは @top-*/@bottom-center しか触らないので隠しノンブルは全ページに残る(折丁照合用として正しい)。nikko-pc の「ノド天地中央・回転」はこれで再現でき、vivlio-pdf の実ビルドで確認した。厳密な mm オフセットや裁ち落とし内配置はマージンボックスの固定位置では表せない(機能は足りる)

## 6. Typst(review-book theme)での指定

### 6.1 対応表

- 設計値は `theme.typ` の `default-theme` 辞書に置く。構造は3章の区分と同じ(`text` / `margins` / `fonts` / `colors` / `box` / `crop`)
- 書籍側の記述場所はプロジェクト直下(config.yml の隣)の `theme.typ` で、著者が自分で置き、ビルドがそのままコピーして使う。形は `merge-theme(default-theme, (...))` で、上書き辞書に3章の語彙名のまま設計値を書く
- `theme.typ` が無ければ既定の雛形が作業ディレクトリ内に生成されて使われる。作業ディレクトリはビルドごとに作り直されるので、雛形は著者の手元には残らない
- config.yml の `typst:` 名前空間は版面値を持たない。用途の意思表示(`crop` の強制など。LaTeX の `media` に相当)だけを置き、`typst.crop` はテーマ設定に優先する

| 語彙 | theme.typ |
|---|---|
| paper | `paper: "jis-b5"` |
| binding / two-sided | `binding: "left"` / `two-sided: true` |
| fontsize / baselineskip | `text.size: Q(13)` / `text.baselineskip: Q(21.65)` |
| line-length / number-of-lines | `text.line-length: 40` / `text.number-of-lines: 35` |
| head-space / gutter | `margins.head-space` / `margins.gutter` |
| headsep / footskip | `margins.headsep` / `margins.footskip` |
| 級数表 | `text.xxlarge` 〜 `text.xsmall`(倍率のまま持つ) |
| 書体 | `fonts.body / heading / code`(配列で欧文先・和文後) |
| 和欧の大きさ | 同寸。フォールバックに大きさ補正の機構がなく、同寸しか書けない |

### 6.2 単位

- `Q(n)` 関数(= n × 0.25mm)で級数・歯送りを書く。pt は書かない(2.4)

### 6.3 行送りの決定性

- `top-edge: 1em, bottom-edge: 0pt` で行箱を固定する。これで baseline 間 = 1em + leading となり、行送りが設計値になる
- Typst の既定(cap-height 基準)のままでは行箱の高さがフォントのメトリクスに依存し、書体を替えると行送りが変わる。2.5 の決定性が崩れる代表例である

### 6.4 版面の外

- 版面の値(headsep / footskip / 級数)はテーマが持ち、柱とノンブルの描き方は `renderers`(running-head / page-number)が持つ。位置と描画の分担は 2.9 のとおり
- 地と小口の導出は `text-block-size` 関数(字詰め×級数、行数×行送り)から `book.*` 側が行う

### 6.5 トンボと入稿

- トンボと裁ち落としは物理的に描く。Typst は TrimBox も出力インテントも書き出せず、仕上がり位置を伝える手段が他にない
- `crop.sheet` に判型名を指定すると標準用紙の中央に仕上がりを置く(2.10 の日本の入稿形)。Typst は判型名から寸法を引けないため、主要判型の寸法表はライブラリが持ち、表にない判型は `crop.trim` で明示する
- CMYK と PDF 適合モード(PDF/A・PDF/UA)は排他なので、適合モード時はトンボ色を通常の黒に落とせる

## 7. 各エンジンの相違

### 7.1 導出（計算）を行う場所の違い

- 同じ「天とノドだけ指定」の規約でも、残りを計算する場所が違う
  - LaTex: クラスが計算する
  - CSS: 書き手が calc() で計算する
  - Typst: テーマ関数が導出する
- この違いは失敗の出方に現れる。LaTeX は過剰決定を黙って辻褄合わせし、CSS は計算式の書き漏れが過少決定(ブラウザ既定値の混入)になり、Typst は導出が一箇所なので壊れ方も一箇所である
- 検証するときは「意図した字詰め・行数が出ているか」を三系統とも組み上がりで確認する。指定値の一致は導出結果の一致を保証しない

### 7.2 共有できる指定・できない指定

- 語彙に載せる設計値は、原則として三系統すべてに写せるものに限る。写せない指定は語彙に入れない。和欧比率はこの理由で語彙に入れなかった(2.8)
- そのうえで、語彙に残したが実現手段に差があるもの:
  - TrimBox・出力インテント:Typst は書けず、トンボの物理描画で代替する(6.5)。LaTeX(pdfx 系)とは PDF 内部での表現が異なる
  - headsep / footskip:CSS には直接の対応物がなく、マージンボックス寸法への換算で近似する(5.4)
  - 行送りの決定性:LaTeX と CSS は既定で概ね成り立ち、Typst は明示の指定が要る(6.3)
  - 級数表:LaTeX はクラス定義の命令の寸法(1.2 の冪)、CSS・Typst は丸めた倍率で組まれ、見出しの級数に数%の微差が出る(2.6)

### 7.3 一致の検証

- 同じ設計値から3系統で出力し、突き合わせる:1ページの行数と1行の字数(数える)、版面の四辺の位置(重ね合わせ)、ノンブル・柱の位置
- 判定に使う原稿は、約物や欧文を含まない全角文字のべた組みページを含むこと。禁則やジャスティフィケーションの差で字詰めが揺れると、版面の検証にならない
- これは `tools/hanmen-compare`(`rake hanmen:compare`)で自動化した。design.css の設計値を単一ソースに「田」だけのべた組み1ページを三系統の実設計ファイルで組み、各 PDF から行数・字数・版面四辺(mm)・行送りピッチを測って突き合わせる。水平(字詰め・行数・版面の左右)と行送りピッチは一致を判定し、天地(字面の上端/下端)は Vivliostyle(Chrome)が CJK を Type 3 で埋め、pdftotext がその box を em の約2.6倍に報告するため情報として差分だけを出す(フォントの違いではない。Typst に Hiragino・LaTeX に Harano Aji という別フォントを与えても CID 埋め込みなら両方 em 相当で、同じ Hiragino でも Chrome だと約2.6倍になる。em の位置自体はピッチ・行数・左右で担保する)。LaTeX は jlreq の既定行送り(1.7zw)に流れないよう baselineskip も設計値に固定して組む。typst / uplatex+dvipdfmx / vivlio-pdf の揃った環境で走り、無いエンジンはスキップする

## 9. 対象外と保留事項

### 9.1 やれば片付くもの

- 三系統の紙面比較(7.3)。行数・字詰め・四辺位置を突き合わせる。設計値ファイルの静的照合は test/ast/test_hanmen_design_values.rb、実際に組んだ紙面の突き合わせは tools/hanmen-compare で自動化済み
- 欧文フォールバック列の見直し。同寸を既定にしたので、x-height の大きい欧文書体の選定が実益を持つ(2.8)
- 柱・ノンブルの級数(running-head-size / folio-size)の review-jlreq クラスオプション化。jlreq のページスタイルに `running_head_font` / `nombre_font` キーが既にあり、`\ModifyPageStyle` への薄い写像で実装できる(無指定なら発行せず現行の本文同寸のままで後方互換)。本体(kmuto/review)への上流提案となる。
  - review-jsbook 側は fancyhdr のため対象外とし、sty の編集で行う
- エンジン中立の設計値名前空間。多形式で同時に出す本は設計値を texdocumentclass・design.css・theme.typ に重複して書くことになるため、config.yml に3章の語彙そのままの欄を設けて各 maker が注入する拡張がありえる。変換層の維持とエンジン別ファイルとの優先順位の規定が必要なので、実需が出てから設計する

### 9.2 対象外と決めたもの

- CSS(Vivliostyle)で仕上がりを判型名の標準用紙の中央に置く形(2.10 の後者)。crop-offset の文法が `auto | LENGTH` の全辺一律で、軸ごとに余りが違う中央化(A5→B5 など)ができない。一律に大きい用紙へ載せる形は `--crop-offset` で表せる(5.5)。判型名の用紙が要るときは auto の入稿 PDF を後段の面付けで当該用紙に配置する
- jsbook 互換(和欧比率 1.081)。理由は 2.8 の通り。
- 縦組み。Typst が未対応であり、三系統の語彙として成立しない。Typstが対応したら再検討する
- 段組。現時点の対象書籍(技術書)で需要が薄く、余白導出の規約(2.3)が二段組と干渉するため、必要になった時点で設計する

- 9.1 の項目を実ファイル単位の作業に分け、規模・依存・外部要件で並べたもの。完了分は外し、残りだけを載せる
- 完了済み:対称性を埋める一式(theme.typ の figure アキ・柱高さ、CSS・Typst の foot-space/fore-edge 陽指定)、設計値の静的照合テスト、CSS のトンボ有効化(入稿用 print CSS + `--bleed`)、欧文フォールバック列の見直し(CSS・Typst)、Typst の通しノンブル(serial_pagination / startpage)と隠しノンブル(nikko-pc = shippo)

- 対応済み:R5(CSS の隠しノンブル)。入稿用 print CSS の @left-middle/@right-middle にノド天地中央・90°回転(transform: rotate)でページ番号を出す。vivlio-pdf の実ビルドで recto=左・verso=右・回転・全ページ残存を確認。厳密な mm オフセットと裁ち落とし内配置のみ範囲外(マージンボックスは固定位置)
