# Typst renderer / maker の設計

## 1. 目的と想定読者

### 1.1 位置づけと想定読者

- 本書は Typst 出力の生成側(TypstRenderer・TypstMaker)の設計を記す
- 想定読者は、生成側を変更・保守する開発者である。この文書だけで、要素対応の追加や maker の変更といった生成側の作業ができることを目指す

### 1.2 パイプライン全景

- Typst 出力は LaTeX と並ぶ PDF 生成経路である

```text
解決済み core AST
    ↓ TypstRenderer(章ごと)
chapters/*.typ(review.* の呼び出し列)
    ↓ review-book ライブラリ(gem 同梱、ビルド時にコピー)
    ↓ typst CLI
PDF
```

- 全体の不変条件:生成物の中のパスはすべて root(ビルドディレクトリ)絶対で書く。Typst の相対パスは書かれたファイル基準で解決され、生成ファイルとライブラリでは基準が食い違うためである

## 2. コード生成

### 2.1 意味 API だけを出す

- レンダラは直接紙面を書かない。`#block(fill: ...)` のような組版指定を生成せず、意味 API(`review.*`)の呼び出しだけを出す

### 2.2 値の運び方は型で決める

- レンダラが持つ値(原稿由来の文字列、描画済みマークアップ)を `.typ` ソース上の綴りにするときは、「値は行き先に合った経路で運ぶ」を規律とする
- 理由:同じ文字列でも、content ブロックに置くならエスケープ済みマークアップ、str 引数に置くなら引用文字列と、行き先ごとに綴りが違う
- この選択は命名規約ではなく型にしている
  - `Text`:文字。`#content` が `[エスケープ済みマークアップ]`、`#literal` が `"引用文字列"` を返す
  - `Code`:評価される Typst 式。エスケープしない
  - `Expression`:呼び出し式の綴り方を一手に持つ。content 引数は空なら引数ごと省く(契約上 `none` と `[]` は別物であるため)

### 2.3 未知のインラインはエラー

- 未知のインラインはエラーにする
- `Renderer::Base#render_inline_element` の既定は内容の素通しで、黙った脱落が起きるため、上書きして失敗させている

## 3. 番号とラベル

### 3.1 番号は Re:VIEW 側で確定する

- 番号が Re:VIEW 側で確定していることは全レンダラ共通である。ライブラリは番号を再構成しない(契約)ので、レンダラが表示文字列まで作って渡す
- `number-text` は TextFormatter の `format_caption_plain` で確定する。`format_caption` は区切り記号込みであり、区切りは番号とタイトルの間に置くテーマの領分なので使わない
- 見出し番号は SecCounter で数え、`secnolevel` による表示可否も Ruby 側で決める

### 3.2 章ラベル

- 章ラベルは各章ファイルの最初の level-1 見出しだけに付ける
- 理由:`=[nonum]` も level 1 なので1ファイルに level-1 が複数ありえて、ラベルの2回定義は Typst が文書ごと拒否する

### 3.3 脚注と後注

- 脚注は初出の `@<fn>` の位置で本文つきの `review.footnote` を出し、後続参照は `review.footnote-ref` にする
- 番号は供給し、強制はライブラリが行う。これで未参照の `//footnote` があっても HTML と番号が揃う
- 後注は参照位置に `endnote-ref`、`//printendnotes` の位置で一覧を出す

### 3.4 ラベルの構成と参照

- 番号付き要素のラベルは `kind:chapter:item` の3要素である(図・表・リスト・数式・コラム・後注・節)
- 章 ID を含める理由:要素 ID は章スコープなので、章 ID なしでは章間で衝突する
- 2要素のものもある:章は `chap:章キー`、書誌は `bib:項目`、`//label` は `label:項目`。書誌は書籍全体で一意なので章で修飾しない
- 章キーは章 ID をそのまま使う。章を持たない場合(部など)は固定文字列 `book` に落とす。オブジェクト同一性や実行ごとの連番から作るとビルド間で変わってしまうため、偶発的な値を避けて固定値にしている
- 参照は `review.reference`(link + 供給表示文字列)で出し、Typst の `ref` は使わない(自前の番号を生成してしまう)

## 4. 要素の変換

### 4.1 対応表が正である

- 要素ごとの扱いは `schema/review-elements.yml` を正とする
- 全61ブロック命令と全57インラインを `render` / `ignore` / `lowered` で記録し、テストがコンパイラの命令表とレンダラの定義メソッドの双方と機械的に突き合わせる
- `ignore` は `//bpo`、`//parasep`、`@<dtp>` の3件だけで、理由を表に明記してある
- 以降の節で特記するのは判断が要った要素だけである

### 4.2 数式

- `//texequation` と `@<m>` の本文は LaTeX 記法で、レンダラは記法のまま `latex:` 引数に渡す
- 変換はライブラリの math アダプタが担い、既定は verbatim 表示、`typst.math: mitex` で差し替える
- mitex はバージョンを 0.2.7 に固定している。パッケージと Typst 本体の互換は版の組で決まるためで、実例として 0.2.5 は現行の Typst でコンパイルできない(kai シンボルの廃止に未対応。0.2.6 で修正)。上げるときは実ビルドで確認すること
- `@<m>` 内の `}` は Re:VIEW の規約で `\}` とエスケープする(全出力形式で共通)

### 4.3 //graph

- GraphImage が外部生成器で SVG を作ってから、通常の図として描画する(IdgxmlRenderer と同じ分割)

### 4.4 画像

- builder 名は `typst` で、`//embed`/`//raw` の対象判定と `images/typst/` の優先探索の両方に効く
- 代替テキストはキャプションから取る。HTML が alt 属性に入れるのと同じ文字列で、両形式の画像の説明が一致する

### 4.5 //embed と //raw

- 任意の Typst コードをそのまま通す経路であり、信頼された原稿を前提とする
- root 外へのファイルアクセスは Typst 自身が拒むが、コードの実行は無制限なので、信頼できない原稿を処理する環境では使わせない判断が要る(無効化設定は保留。9章)

## 5. TypstMaker

### 5.1 本体の maker を継承しない

- `PDFMaker#generate_pdf` は LaTeX ツールチェーン(LATEXBuilder、`ImgGraph(..., 'latex')`、`.tex` マスター生成、sty 配置)を1メソッドに固定で抱えており、継承してもほぼ全経路を override することになって利点が残らない
- 本体から再利用するのは Configure、Book::Base、I18n、Loggable、MakerHelper だけである

### 5.2 ビルドレイアウト

```text
<basedir>/<bookname>-typst/     ← typst --root
├── book.typ                    ← 生成 root(区分切替・体裁)
├── theme.typ                   ← 原稿側に theme.typ があればコピー、なければ生成
├── chapters/*.typ
├── images/                     ← 描画の後にコピー(//graph が描画中に画像を作るため)
├── lib/review-book/            ← gem 同梱ライブラリのコピー
└── source-map.json
```

- 作業ディレクトリは `debug: true` または `typst.keep_workdir: true` で残る

### 5.3 ライブラリはコピーで同梱する

- ライブラリはパッケージ解決ではなくファイルコピーである
- 理由:オフラインで動き、レンダラとライブラリが常に同一 gem の版で組になる

### 5.4 カレントディレクトリ

- ビルド全体を basedir をカレントディレクトリにして実行する
- 理由:依存している review 5.11 は複数のパスをプロセスのカレントディレクトリ基準で解決する(`Book::Part` の本文を読む contentdir、`//graph` が画像を書く imagedir)。別ディレクトリから呼ぶと、パートの本文が黙って空になる
- 上流はどちらも書籍基準に直したので、それを含む版がリリースされて依存の下限が上がれば chdir は不要になる(9.1)

### 5.5 設定

- 設定は `typst:` 名前空間に置く

```yaml
typst:
  command: typst        # CLI 名。検出とバージョン検証を行う
  pdf_standard: ~       # 例 "ua-1"
  math: ~               # "mitex" で LaTeX 数式を mitex で組む
  crop: ~               # true でトンボと裁ち落とし(テーマ設定を上書き)
  index: false          # 索引ページを出す
  keep_workdir: false   # 生成した .typ を残す
  output: ~             # 既定 <bookname>-typst.pdf
```

- 参照する既存キー:`coverimage`、`cover`(トンボ有効時は表紙を出さない既定を `true` で強制。review-jsbook と同じ意味)、`titlepage`、`toc`、`toclevel`(目次の深さ。`review.toc` の `depth` として渡し、テーマの `toc.depth` より優先する。EPUB・LaTeX も同じキーを見るため、形式間で目次の深さを揃える)、`colophon`、`colophon_order`、`history`、`rights`、`dictionary`、`secnolevel`、`caption_position`、`debug`

## 6. 診断と source map

### 6.1 診断への原稿位置の併記

- Typst の診断は生成された `.typ` の位置を指すが、著者が書いたのは原稿である
- レンダラは章ごとに「生成ファイルの行範囲 → 原稿位置」の対応(トップレベルブロック粒度)を記録し、maker が診断の各位置に原稿位置を併記する

```text
error: unknown variable: ...
  ┌─ book-typst/chapters/ch01.typ:9:1  <- ch01.re:7:1
```

- 生成側の位置も消さない。コンパイラが実際に読んだのはそちらである

### 6.2 source-map.json

- 対応表は `source-map.json` としてビルドディレクトリにも書き、`keep_workdir` で後から追跡できる
- ブロックの内側の何行目かまでは辿れない(保留事項。9章)

## 7. 生成コードの注意点

- Typst コードを生成する側が知らないと壊す事項の一覧である。ライブラリを書く側の注意点は `typst-review-book.ja.md` の6章にある
- `//` はコンテンツモードでも行コメントを開始する。本文中の「//list」のような記述もエスケープが要る
- `--` は en ダッシュ、`...` は省略記号にリガチャ化される。行頭の `- ` `+ ` `= ` `/ ` `1. ` はリスト・見出し・定義リストの項目になる(`/ ` は用語の項目)
- 箇条書きと定義リストを markup 構文で生成しない。項目内容の `:` や `/` が構文と衝突する。関数呼び出しに content の配列で渡す
- パスは root 絶対で書く(1.2 の不変条件)

## 8. 検証と変更の手引き

### 8.1 3層の担保

- パリティのオラクルがないため、3層で担保する
  1. 要素の網羅:`schema/review-elements.yml` をコンパイラの命令表・レンダラの定義メソッドと双方向に突き合わせる。表から漏れた命令、表にあって実装がない命令、`ignore` と申告しながら出力する要素のいずれもテストが落ちる
  2. 番号の一致:同じ原稿を HtmlRenderer と TypstRenderer で描画し、見出し番号を比較する。期待値そのものも固定してあり、両者が空を返す空虚な合格はできない
  3. 実物のビルド:全区分とパート2種を含む構造テスト、samples の2冊のビルド、PDF/A・PDF/UA は Typst 自身の適合検査と veraPDF の二段

### 8.2 CI

- CI は `.github/workflows/typst.yml` として独立している。外部の組版エンジンを要するため
- CJK フォントも入れる。ないと Typst が黙ってフォールバックし、日本語を一度も組まずにテストが通ってしまう
- veraPDF も入れる。テストは実行ファイルがなければ二段目の検査を黙って飛ばすので、入れないと適合の回帰に気づけない(CJK フォントと同じ罠である)

### 8.3 変更の手順

- 要素への対応を足す:visit メソッドまたは inline handler を実装し、`review-elements.yml` を更新する(しないと網羅テストが落ちる)。レンダラのテストを足し、新しい経路なら構造テストの fixture にも足す
- Typst や mitex の版を上げる:7章とライブラリ文書6章の一覧を再確認する。mitex は版と Typst 本体の互換が崩れた前歴がある(4.2)

## 9. 対象外と保留事項

### 9.1 やれば片付くもの

- `//graph` の gnuplot / blockdiag / seqdiag / actdiag / nwdiag は未検証(graphviz は確認済み)。mermaid は playwright が前提
- `typst:` 名前空間の不明キーへの警告。綴りを間違えた設定(`keep_workdir` など)が黙って無視される
- 信頼できない原稿向けに `//embed`/`//raw` を無効化する maker 設定(4.5)
- PDF/UA 指定時の数式の代替テキスト。現行は verbatim / mitex のいずれかで組むが、代替テキストを必須にするかは未決
- 索引の読み順は `dictionary` がない書籍ではコードポイント順になる
- source map の粒度はトップレベルのブロック単位(6.2)
- ビルド時の `Dir.chdir` の解消(5.4)。上流が contentdir と imagedir を書籍基準に直したので、それを含む review がリリースされ、依存の下限を上げられた時点で外せる

### 9.2 対象外と決めたもの

- PDF/X(Typst 側が未対応。ライブラリ文書5章)。上流が対応したら再検討する
- 面付け。折丁への配置は印刷所または専用ツールの工程である
- Typst Universe への公開。`book.*` の直書き用例と API の安定が前提で、それまでは同梱コピーが運用上も有利である
- `typst` gem(コンパイラの Ruby バインディング)の採用。CLI で足りており、gem 経由では PDF 標準指定が使えない

### 9.3 こちらでは確定できないもの

- 印刷所への実入稿。寸法、トンボ位置、フォント埋め込み、PDF/A 適合までは機械的に確認済みである。残る不確実性は印刷所ごとの個別要件にあり、初回は小さく試すこと
